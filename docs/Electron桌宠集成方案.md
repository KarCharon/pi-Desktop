# Pi Desktop 集成 dsh-pet 桌宠方案

## 1. 目标与结论

采用“保留 Electron 桌宠运行壳，由 Qt 提供宿主适配”的方案：不安装 DSH、不迁移主界面、不引入 Qt WebEngine，不重写现有宠物动画和物理交互。

Pi Desktop 通过独立 QProcess 启动桌宠；桌宠使用原有透明置顶窗口显示在 Windows 桌面，跟随当前 Pi 会话展示工作状态和余额。

本文件的 Qt 宿主适配层和固定版本运行包构建流程已落地，包含可选开关、生命周期、JSONL/HTTP 桥接、安全边界、Agent 状态和余额快照。当前已在本机生成 `build/pet` 运行包，但真实透明窗口、多屏和点击穿透仍需在 Windows 图形环境完成验收。

### 调研依据

- 上游：https://github.com/PC2005-cloud/dsh-pet
- 调研源码提交：`631c5310b047931404978152fdc7865413c153ec`
- 上游重点文件：
  - `dsh-pet/runtime/electron-helper/main.js`：窗口、进程存活、桥接协议。
  - `dsh-pet/runtime/electron-helper/renderer.js`：配置读取和桌宠实例。
  - `dsh-pet/runtime/electron-helper/events.js`：状态、余额和气泡轮询。
  - `dsh-pet/src/host/helper-process.ts`：原宿主进程管理和桥接类型。
  - `dsh-pet/src/host/index.ts`：宿主路由契约。
- 本项目重点文件：`CMakeLists.txt`、`src/agent/AgentSessionController.h/.cpp`、`src/config/DeepSeekBalanceController.h`。

## 2. 首版范围

### 包含

- Windows 单只独立桌宠，默认关闭，用户主动开启。
- 待机、随机动作、点击反馈、拖动、甩抛、右键动作选择：尽量保留上游实现。
- 当前 Pi 会话的思考、工作、整理、等待、成功、出错动画。
- 复用现有 DeepSeek 余额查询结果，展示余额动画和气泡。
- 启用/关闭、大小、初始位置、工作状态联动、余额联动设置。
- 随主程序退出；故障隔离及有上限的自动重启。
- 缺少运行时或素材时给出明确提示，聊天功能继续正常工作。

### 暂不包含

- 浏览器内 overlay、嵌入 Pi 主窗口的宠物。
- 宠物聊天、自动碎碎念、长期记忆、额外模型调用。
- 多宠物配置界面、第三方 pet pack 导入与在线市场。
- 新增其他服务商余额接口、系统通知功能。
- 首次启动自动下载 Electron 或素材。
- 跨 Pi Desktop 实例的全局桌宠协调。

保留基础交互不等于已经验证上游所有行为；多屏和点击穿透仍须在目标机器实测。

## 3. 架构

```text
Pi Desktop（Qt/C++）
  ├─ AgentSessionController ── 结构化状态 ─┐
  ├─ DeepSeekBalanceController ─ 余额快照 ─┤
  ├─ AppSettings ───────────── 用户设置 ──┤
  │                                      ▼
  └─ PetController（QProcess 生命周期）
       └─ PetBridge（请求解析、路由、响应）
            ▲                          │
            │ stdout 前缀 JSONL 请求   │ HTTP POST 回调响应
            │                          ▼
       Electron Helper 主进程
         ├─ 自定义 dsh-pet-bridge:// scheme
         ├─ 127.0.0.1 随机端口回调服务器
         └─ 透明置顶局部窗口
              └─ renderer + shared-core + WebM 素材
```

### 核心约束

1. Qt 是会话状态、配置和余额的事实源，桌宠只负责展示与交互。
2. 桌宠使用独立进程，不共享 Pi RPC 的输入输出管道。
3. 不直接复制上游整个 host：它依赖 DSH 服务注入、凭证、模型、命令等能力。
4. 用 Qt 重建最小兼容路由，复用 Electron 壳、渲染端及 shared 纯逻辑。
5. 首版不新增常驻 Node 服务。Node/npm 仅用于构建桌宠资源，运行由 Electron 承担。

## 4. 通信协议：必须按源码实现

### 4.1 请求和响应不是双向 stdin/stdout

上游部分说明将桥接称为 stdin/stdout 协议，但当前实现是：

- **请求**：Electron stdout 输出 `dsh-pet-bridge:` 前缀加一行 JSON。
- **响应**：Qt 向请求携带的本机 `cb` 地址 POST JSON。
- 原因：上游为绕开 Windows Electron piped stdin 接收问题，使用本机 HTTP 回调。
- 素材二进制不走管道，Qt 返回经过验证的绝对路径，Electron 读盘。

请求示意：

```json
{
  "id": 1,
  "method": "GET",
  "url": "/dsh-pet-7340/config",
  "cb": "http://127.0.0.1:49152/respond"
}
```

JSON 响应示意，`body` 为序列化后的字符串：

```json
{
  "id": 1,
  "status": 200,
  "contentType": "application/json",
  "body": "{}"
}
```

素材响应示意：

```json
{
  "id": 2,
  "status": 200,
  "contentType": "video/webm",
  "file": "E:/PiDesktop/pet/assets/webm/example.webm"
}
```

以上仅说明信封格式；配置响应不能真的用空对象，必须返回符合上游成品配置契约的数据。

### 4.2 Qt 解析策略

- 使用独立缓冲区按 LF 拆行，支持拆包、粘包、CRLF 和中文 UTF-8。
- 仅识别前缀行；其余 stdout 和 stderr 作为有界诊断信息。
- 校验 id、method、url、body、cb 的类型、长度和允许值。
- 设定单行、缓冲区、请求体及并发请求上限；协议破坏时停止桌宠，不影响 Pi。
- 每次启动生成进程代次，异步响应必须关联代次，不能把旧回调发给重启后的进程。
- HTTP 回调使用独立 QNetworkAccessManager，明确 NoProxy，禁止重定向。
- 回调异步完成，不阻塞 GUI 线程；失败只有限重试，不能无限积压。

### 4.3 必须补齐的安全边界

上游当前回调入口不能直接作为安全完成态照搬。移植补丁需增加：

- 每次启动生成随机令牌，通过专用环境变量交给 helper；回调必须带认证头并验证。
- 回调仅绑定 `127.0.0.1`；Qt 仅接受 `http://127.0.0.1:<port>/respond`，拒绝 userinfo、查询串、片段和其他地址。
- 首个合法回调地址与当前进程代次绑定，运行期间不允许任意切换。
- 回调服务器限制请求体大小，校验响应 id 是否属于当前待处理集合。
- 素材路径必须位于批准的资源根；解码、规范化并检查实际文件路径，拒绝目录穿越、绝对路径注入和越界符号链接。
- 不向 helper 传递 API Key、auth.json 内容、Pi 提示词或工具输出；启动环境去掉模型凭证变量，仅保留必要环境。
- 保持 Electron 上下文隔离；不扩大渲染端 Node 权限；外部链接只允许批准的 HTTPS 地址。

## 5. 最小宿主路由

首版保留 `/dsh-pet-7340` 前缀，以降低对 renderer 的改动。它是内部兼容标识，不表示需要部署 DSH。

| 路由 | 首版行为 |
| --- | --- |
| `GET /config` | 返回按上游格式合并、校验后的成品配置；仅一只 `display=desktop` 宠物 |
| `GET /thumb/<素材根>/<动画名>.webm` | 白名单资源映射，返回本地文件路径 |
| 字体、图标、光标等资源路由 | 以固定版本真实请求为准补齐，不做任意文件服务器 |
| `GET /work-status` | 返回当前 Pi 会话工作状态快照 |
| `GET /balance` | 返回现有余额控制器的缓存快照，不因轮询直接请求官方 API |
| `/balance/trigger` | 按上游计数契约兼容；手动刷新动作调用现有受限刷新入口 |
| `GET /broadcast` | 未启用聊天时返回空广播：`ok=true,text="",ts=0` |
| `GET /notify` | 通知关闭；如仍有请求，返回空帧及稳定序号 |
| `/whisper`、`/whisper/trigger`、`/chat` | 首版隐藏入口并停用轮询；漏入请求返回明确的不支持响应 |
| 配置写入和管理类路由 | 首版设置由 Qt 管理，默认拒绝未实现的写操作 |

实施前从固定提交的 shared 类型和 host 响应提取契约测试夹具，核对余额、工作状态、资源 URL 的精确字段。不能仅按 README 猜字段。

特别注意：`/config` 返回的是按种类组织的完整聚合，不是直接发送原始 `config.jsonc`，也不是只发送 `pets` 数组。需要填齐动画池、权重、物理参数和事件配置。

首版可在构建阶段从固定上游默认配置生成标准 JSON 基线，运行时仅覆盖批准的用户设置；避免在 C++ 中重复实现整个 DSH 配置系统。

## 6. Pi 工作状态映射

### 6.1 数据入口

在 `AgentSessionController` 的现有事件处理路径增加结构化展示状态信号，由 `PetStateAdapter` 消费。不解析 `statusText` 的中文显示文案，也不把 `busy=false` 一律解释成成功。

`thinkingLevel` 是思考等级设置，不是“当前正在思考”的运行状态，不能作为动画触发信号。

| Pi 情况 | 桌宠状态 |
| --- | --- |
| 请求已接受，等待模型或正在生成 | 思考 |
| 工具正在执行 | 工作 |
| 上下文压缩进行中 | 整理 |
| 等待扩展输入、确认或用户选择 | 等待 |
| 整轮确实完成，且没有失败、取消或后续工作 | 成功，播放一次 |
| 模型/运行异常，或按产品规则判定的最终失败 | 出错，播放一次 |
| 用户中止、会话切换、断开后无任务 | 待机或明确取消/断开提示，不庆祝 |

### 6.2 状态一致性

- 状态附带会话标识、运行代次和变化序号/时间戳，输出时转换成上游需要的契约。
- 忽略旧会话、旧进程、旧任务的迟到事件。
- 工具结束不等于任务结束，`turn_end` 也不能直接当成整轮成功。
- 工具级失败允许被后续恢复，不应立即锁死整个任务为失败。
- 用户等待和压缩状态优先于普通生成；结束后恢复当前真实状态。
- 成功/失败终态保留足够展示时间，保证约一秒的轮询能观察到；新任务立即覆盖旧终态。
- 断开和取消必须覆盖旧 busy 状态，避免宠物永久工作。
- 首次启动和重连的基线语义须测试：不能重播旧庆祝，也不能漏掉当前正在工作的状态。

## 7. 余额复用

现有 `DeepSeekBalanceController` 已负责账户选择、刷新、超时和错误处理，桌宠不得再维护另一套官方请求。

当前公开属性主要是展示文本和可用状态，实施时需补只读结构化快照接口，提供金额、币种、可用性、原因和更新时间；不得从 `displayText` 中截取金额。

- `/balance` 只读取快照；桌宠轮询频率与官方 API 刷新频率分离。
- 原有五分钟刷新、手动刷新、超时与重试策略保持不变。
- 桌宠右键查看余额如要刷新，必须经过原控制器的合并与限流策略。
- 切换 Profile、账户或 provider 时立即使旧余额失效。
- 非 DeepSeek、未启用、缺凭证、请求失败分别给出可区分的不可用原因。
- 不把 API Key 或账户认证传给 helper。
- 上游默认以 ¥20 折算余额档位，该数值只是展示阈值，不是账户额度；首版需明确采用可配置“充足余额参考值”，不能宣称是真实用量百分比。
- 外币与阈值币种不匹配时不做隐式汇率换算，保留文字展示。

## 8. 进程和设置

### 8.1 生命周期

1. 应用加载设置；桌宠关闭则不创建进程。
2. 检查固定运行时、helper、shared-core 和必要素材是否完整。
3. 生成令牌和进程代次，通过 QProcess 启动指定 Electron 可执行文件。
4. 设置 `DSH_PET_BRIDGE=1`、`DSH_PET_HOST_PID` 和配置 URL 等上游必要变量；清除 `ELECTRON_RUN_AS_NODE`。
5. 首次配置成功且渲染端报告就绪后才标记可用，不能仅凭 QProcess 启动成功判断。
6. 关闭开关或应用退出时先请求优雅退出，超时后终止自己创建的进程树。
7. 父进程异常消失时保留上游 PID/管道存活守卫作为兜底；Windows 可评估 Job Object 约束子进程树。

建议重启策略：异常退出按 1、3、10 秒退避，五分钟内最多重启三次，之后停止并显示错误；用户主动关闭及应用退出不重启。计数不能每次短暂启动成功就清零。

Pi Agent 重连或切换工作目录只更新桌宠快照，不必重启 Electron。资源或必须重建的配置变化才重启桌宠。

### 8.2 设置与多窗口语义

- 全局设置保存启用意愿、大小、位置和联动开关，不写入 Pi Profile。
- 桌宠位置和 Electron userData 使用 Pi Desktop 专用目录，不复用 `%APPDATA%/Electron` 或 `~/.dsh`。
- 本项目允许启动多个独立主窗口；首版每个主窗口只管理自己的 helper，绝不通过进程名批量结束 Electron。
- 不实现全局单例时，多窗口可能各自显示一只宠物，设置说明需明确这一行为。
- 多实例 Electron 缓存/userData 需实例隔离，避免目录锁冲突；位置等持久化配置由 Qt 统一负责。

## 10. 构建与发布

- 固定上游提交、依赖锁文件与已验证的 Electron 版本；不能依赖运行时自动获取 latest。
- 在受控构建阶段审查并执行上游完整 prepare 流程或等价的最小构建流程。
- `shared-core.js` 是构建产物，不在当前源码运行目录直接现成提供；只复制 `runtime/electron-helper` 不足以运行。
- 清点 HTML、preload、renderer、sprite、events、辅助 JS、shared-core、字体、光标、图标和配置的传递依赖。
- 在工程根目录执行 `node scripts/build-pet-runtime.mjs`；脚本校验上游提交 `631c5310b047931404978152fdc7865413c153ec`，使用 `127.0.0.1:7897` 安装 npm 依赖和下载 Electron，并输出 `build/pet`。
- Electron 必须携带完整运行目录，不能只复制 `electron.exe`。
- 首版采用可选离线资源包；没有资源包时主程序照常启动，桌宠提示未安装。
- 发布包保留 MIT 声明、Electron/Chromium 等第三方许可及来源记录。
- 记录运行包版本、资源清单和 SHA-256；宿主启动前校验 manifest 结构、路径安全性和清单文件存在，发布验收可进一步比对 SHA-256。
- CMake 安装规则只收集已构建产物，不在普通 C++ 编译时联网下载依赖。

建议发布目录：

```text
bin/
  pi_Desktop.exe
  pet/
    runtime/                  # 完整 Electron 运行时
    helper/                   # helper 脚本与 shared-core 构建产物
    assets/                   # 经许可分发的动画、字体、图标
      config.json             # 生成后的 {main: ...} 聚合配置
    manifest.json             # 版本、文件清单和 SHA-256 校验信息
    licenses/                 # 第三方许可和来源
```

体积、内存和 CPU 暂不承诺具体值。用单宠物待机、连续动画、拖拽、任务联动四种场景实测，尤其注意上游 Windows 分支关闭硬件加速后的 CPU 开销。

## 11. 日志和故障隔离

日志前缀：`[PetLifecycle]`、`[PetBridge]`、`[PetState]`、`[PetAssets]`。

必须能区分：

- 开关关闭、运行时缺失、配置非法、素材缺失。
- 不支持的 provider、余额数据不可用、会话信息不足。
- 启动失败、协议错误、回调失败、渲染加载失败、异常退出。
- 桌宠成功就绪、配置成功应用、正常关闭。

禁止在逐帧动画、逐 Token 回调、每次轮询和逐素材加载中打印常规日志。重复失败累计计数，恢复或达到节流窗口时输出一条摘要；状态通知只在有意义的转换时记录。

日志不得包含令牌、API Key、提示词、工具输出或完整用户认证路径内容。无论桌宠怎样失败，都不能中止 Pi 任务或改变聊天会话。

## 12. 实施顺序与验收

### 阶段 A：独立运行验证

使用固定配置和少量获准素材，验证 Qt 能启动 helper，完成配置与素材桥接。

验收：透明背景、无 CMD 窗口、点击拖拽正常；退出主程序后 helper 及渲染进程消失；无需安装 DSH。

### 阶段 B：宿主适配与设置

实现桥接、令牌、资源白名单、配置、开关、生命周期和有限重启；关闭未实现菜单及轮询。

### 阶段 C：状态与余额

接入结构化状态信号和余额快照，保留任务代次及终态观察窗口。

验收：多轮工具调用不提前庆祝；取消不庆祝；压缩、等待、错误、切会话、重连和快速结束都展示正确；余额轮询不增加官方 API 调用次数，账户切换不残留旧金额。

### 阶段 D：发布回归

验证干净 Windows 环境、中文/空格路径、无联网、缺文件、多屏不同 DPI、任务栏边界、休眠恢复、全屏应用覆盖和多 Pi Desktop 实例。

测量安装体积、内存、CPU、动画切换和状态延迟；检查退出是否有残留进程。正式验收前不宣称完整继承上游跨平台兼容性。

### 工期口径

此前所说的 2～4 天更适合作为“基础单宠物联动原型”的粗估，不包含完整安全加固、干净机器打包、多屏回归和许可确认。阶段 A 完成后再根据实际兼容问题估算发布版，不把调研估计当成交付承诺。
